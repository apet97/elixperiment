## Rules

1. Do not mark a task `COMPLETE` because code appears to exist.
2. Record exact evidence: Git SHA, commands, results, tests, migrations, and live/deployment evidence where relevant.
3. Reverify direct prerequisites before beginning a task.
4. Mark stale evidence `REVERIFY` after a related architectural or behavioral change.
5. Preserve prior evidence and notes. Do not rewrite history to make progress look cleaner.
6. Use the task's completion gate in the canonical plan as authority.
7. A blocked live/deployment task does not block independent offline work.
